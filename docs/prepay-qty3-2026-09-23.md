# "Eerste 3 maanden" as the package at quantity 3 (2026-09-23)

Branch `fix/prepay-qty3-discount-2026-09-23`. It replaces the prepaid PROMO product model of
`docs/prepay-promo-lineitems-2026-09-22.md` (PR #93).

## The model

A package purchase is exactly two cart lines:

| Line | Quantity | Price |
|---|---|---|
| Installation product: Climax `CL003`, or the NAMI option the customer picks | 1 | full price, never discounted |
| The real package product (e.g. `N0002` Zeker) | 3 (`promo.months`) | 50% off, applied by Shopify |

The 50% comes from the existing automatic discount "Eerste 3 maanden". The theme computes no
discount, creates no products and never changes the discount. From month 4 Odoo bills the
plain monthly rate over SEPA. See **Pre-live-push checks** below: this part is not confirmed yet.

**Hard rule (Thijs, 2026-09-23): never create products.** The only products sold on this site
are the ones in the table below. Odoo's contract automation keys off these products, and every
new Shopify product becomes a stub product in Odoo. Never modify products or the discount from
this repo either.

## Why the PROMO-* approach was abandoned

PR #93 (merged 2026-09-22) sold the promo as five separate products, "Eerste 3 maanden korting —
<pakket>" (`eerste-3-maanden-<pakket>`, SKUs PROMO-INZ/ZEK/BES/ALE/PRO). The plain package product
never went into the cart.

Every new Shopify product becomes a stub product in Odoo. **A `PROMO-ZEK` stub now exists in Odoo
and is left there for Odoo-side cleanup** (outside this repo). The five products were deleted from
Shopify on 2026-09-23. On `main` that left every add-to-cart flow adding nothing, because each one
still looked up its promo product. The store is password-protected, so no rollback was needed.

This branch removes every PROMO-* / `eerste-3-maanden-*` reference and the `promoProduct` config
fields. It also removes the `zv_promo_live` theme setting: the Shopify discount is now the only
switch. `check_pricing.py` check #9 fails if any of these come back.

## Rounding: what Shopify actually charges

**Shopify rounds per unit, not per line.** It takes 50% of the unit price, rounds each unit's
discount down (e.g. €12,475 → €12,47 off), and multiplies by 3. Each unit of a package whose
50% lands on a half cent costs half a cent more than the config expects, so the package line is
**1 cent above** the config's half-up figure. Measured in real carts on the validation theme:

| Combination | Config (brief) | Shopify charged | Package line |
|---|---|---|---|
| Zeker · geen | €37,43 | **€37,44** | 3 × €12,48 (discount €37,41) |
| Zeker · telefonisch | €72,43 | **€72,44** | same |
| Zeker · aan huis | €136,43 | **€136,44** | same |
| Beschermd · aan huis | €158,93 | **€158,94** | 3 × €19,98 (discount €59,91) |
| Protect · aan huis | €155,93 | **€155,94** | 3 × €18,98 (discount €56,91) |
| Inzicht (3 options) | €29,93 / €64,93 / €128,93 | not measurable* | expected 3 × €9,98 = €29,94, so +1 cent |
| Alert (3 options) | €37,43 / €72,43 / €136,43 | not measurable* | expected +1 cent, same as Zeker |

\* N0001 and N0003 can't be added to a cart yet ("sold out"; see the checks below).

**The config has not been changed** (the brief says not to). Consequences:
- Cart, Overzicht and checkout always show and charge Shopify's real amount, e.g. €37,44. They
  read the line prices and never recompute.
- The actie page and the config's `promoDiscountTotal` / `dueToday` show the half-up figure,
  e.g. €37,43. A customer would see €37,43 on the actie page and pay €37,44.

**Decision needed (Thijs):** either set the config to Shopify's per-unit result, 3 × (unit − floor(unit
× 50%)), or accept the 1-cent gap.

## How the theme enforces the model

- **Add-to-cart** (Oplossingen cards and "Meer informatie" modal, Vergelijk pakketten, the
  embedded package matcher):
  - adds the package variant at `promo.packageCartQuantity` (3);
  - adds CL003 only for a Climax package (`installGroup` from the pricing config);
  - never adds a package that is already in the cart, since that would add months.
- **Package identity** is read from the package line:
  - Liquid: `product.type` + `custom.finder_key`;
  - the Cart AJAX guard: product type + handle, because it can't see metafields.
- **"Daarna €X/mnd"** is the package line's unit price before the discount
  (`item.original_price`), never unit × 3.
- **Cart guard** (`snippets/zv-cart-guard.liquid`, on `/cart` and Overzicht) fixes one thing per
  load, then reloads:
  - package line → quantity 3;
  - duplicate package line → removed;
  - installation line → quantity 1;
  - Climax package without CL003 → CL003 added;
  - CL003 in a cart without a Climax package → removed.

  It never picks a NAMI option for the customer.
- **Checkout gate** (Overzicht, server-side) disables checkout while any of these is true:
  - `cart_needs_activation`: installation line missing;
  - `cart_needs_fix`: anything the guard is still fixing;
  - `cart_pkg_undiscounted`: a package line with no discount at all, e.g. if the Shopify
    discount is ever deactivated. The guard can't fix that, so checkout stays blocked with
    "Er ging iets mis met uw bestelling. Neem contact op via 088 122 11 11." **A customer can
    never pay 3 full months.**
- **Quantity controls:** package and installation lines on `/cart` have no +/−. The add-to-cart
  drawer only has "remove".
- **GA4:** `item_id` comes from the line's own SKU (`assets/zv-track.js`, and the SKU property
  on add-to-cart), so it reports N0001/N0002/N0003 from the live cart with no code change.

## Found but not fixed (outside this brief)

- **Product titles.** The Odoo titles "Nami Langer Thuis Zeker" / "Nami Mijn Thuis Alert" make
  the Oplossingen card, matcher and drawer names come out as "Nami  Zeker" (`short_name` = title
  minus the section's eyebrow). The cart and Overzicht item rows show the full Odoo title. The
  breakdown rows use the config names ("Zeker × 3 — …").
- **Overzicht copy.** The schema defaults `due_today_text` ("…plus de vooruitbetaalde korting voor
  de eerste 3 maanden…") and `before_explainer` ("De korting van de eerste 3 maanden rekent u
  vandaag ineens af…") were written for the PROMO model. `promo.disclosure` would be a drop-in
  replacement.
- **ICV.** `activation + monthly × term − promoDiscountTotal` is equivalent to install + prepaid 3
  months + monthly × (term − 3) only when the prepaid amount is exactly 1,5 × monthly. With the
  rounding above it is 1–2 cents low (e.g. Zeker €360,97 vs €360,99), and `recurringMonthsBilled`
  still says `term`.
- **NAMI install de-duplication** in the guard keeps the *oldest* of two NAMI install lines, not
  the newest its comment says (`/cart.js` lists newest first). This was already the case before
  this change.
- A NAMI cart before the customer's install choice shows "We herstellen dit automatisch", which
  it doesn't. Also pre-existing.
- The GA4 `add_to_cart` event sends quantity 1 at the monthly price, not 3 at today's amount. The
  purchase value is the real cart total.
- No store page uses the `actie` template (`templates/page.actie.json`), so the actie page isn't
  reachable on the storefront yet. It was validated via `?view=actie`.
- `pricing/pricing.schema.json` is stale (e.g. it requires `contractTerm`) and nothing enforces it.
- Three old `zz-validate-*` themes from earlier sessions are still on the store.
