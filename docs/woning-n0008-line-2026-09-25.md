# Woning: NAMI only, collected by one priced N0008 line (2026-09-25)

Branch `feature/woning-n0008-line-2026-09-25`, from `origin/main` @ `5d3a31f`. It replaces the
2026-09-24 model "property only, never a priced line" (`docs/woning-surcharge-research-2026-09-23.md`
§9). Scope and mappings are decisions by Thijs, 2026-09-25.

**Blocks merge: N0008's price and discount (§5).** The theme is built for the intended €4,00
unit with 50% promo. Today N0008 is €40,00 and not in the discount, so Overzicht blocks every
checkout that carries it (§3, `cart_woning_bad`).

## 1. The model

- **NAMI only.** The surcharge and N0008 apply only to Inzicht (`langer-thuis-inzicht`), Zeker
  (`langer-thuis-zeker`) and Alert (`mijn-thuis-alert`): `surcharges[extra-etage].appliesTo`.
  Beschermd and Protect (Climax) never get a Woning choice, a Woning property or an N0008 line.
- **The property stays.** The `Woning` line-item property on a NAMI package line is unchanged:
  same values (`1 extra verdieping of 100 m²`, `2 extra verdiepingen of 200 m²`), same legacy
  prefix (`Groter dan 100 m²`, read as 1 floor), same writers (card, modal, drawer). It stays the
  per-package record for Odoo.
- **One N0008 line.** The cart also holds one line of `extra-etage-of-100m2` / N0008 at quantity
  `promo.months` (3) x the sum of floors over the NAMI package lines: 1 floor = 3, 2 floors = 6,
  no Woning = no line. Two NAMI packages with 1 floor each give one line at 6.
- **Money.** N0008 is meant to be in the "Eerste 3 maanden" automatic discount (Admin). Each floor
  then costs 3 x half_up(400 x 50%) = 600 cents today. Odoo bills 400 per floor per month from
  month 4. The ICV adds n x (600 + 400 x (term - 3)).

Where it lives:

| Place | What |
|---|---|
| `pricing/pricing.config.json` `surcharges[extra-etage]` | `shopify` {handle, sku}, `appliesTo`, `collectedVia`, `woning.note`; unit 400 unchanged |

| `scripts/check_pricing.py` §13 | SKU N0008 + handle; appliesTo has no Climax package; 600 per floor today; ICV +4200/+8400 on NAMI, none on Climax; no theme file outside the generated snippets names the N0008 SKU or handle |
| `sections/oplossingen.liquid` | resolves N0008 (`data-woning-variant-id`); `syncWoningLine(cart)`; Climax cards and modal |
| `snippets/zv-cart-guard.liquid` | rules 5 (N0008 quantity) and 6 (Woning on a Climax line) |
| `sections/zv-cart.liquid`, `sections/zv-checkout-overview.liquid` | the "Woning: <value>" row; Daarna/ICV from the NAMI property only; Overzicht gate |

Resolution: `all_products[zv_woning_handle]`, and only if its first variant's SKU is
`zv_woning_sku` (the same pattern as the packages by handle). Unresolved, every surface falls
back to the 2026-09-24 behaviour: property only, no line, no Woning gate, and one `console.warn`
on Oplossingen.

## 3. Cart guard and Overzicht gate

Guard (`snippets/zv-cart-guard.liquid`), lowest priority, one fix per load, all in `planFix`, so
Overzicht's pre-checkout re-check sees them too:
5. Woning line: several lines are merged into one at the target; one line at another quantity
   is set to the target; target 0 removes it; a NAMI cart with Woning but no line (e.g. from
   before this deploy) gets it added (`update.js` by variant id, absolute quantity, so two guard
   runs can't stack it).
6. A Climax package line with a `Woning` property: the property is deleted via
   `/cart/change.js`, quantity and the other properties kept.

N0008 never matches the package rule (type `NAMI_abonnementen`, not `Beveiligingsabonnement`)
or the installation rules (it's none of the installation variant ids).

Overzicht disables checkout with the existing contact message ("Er ging iets mis met uw
bestelling. Neem contact op via 088 122 11 11.") through `cart_woning_bad`, only when N0008
resolves, when the N0008 quantity isn't 3 x the NAMI floors (or it's split over lines), when the
line has no discount, or when its unit `original_price` isn't `zv_woning_unit_cents`. A Climax
line with Woning sets `cart_needs_fix` ("We werken uw bestelling bij…") until the guard's fix.

## 4. Climax (Beschermd, Protect): the hardware page instead (decisions, Thijs 2026-09-25)

- **Cards:** the whole `ltc__uitbreidingen` panel is gone on these two cards: the Woning group and
  the "Extra diensten (optioneel)" / Ontzorgpakket group. In its place, in `.ltc__links`: the link
  "Uitbreiding hardware" to `/pages/camera-hardware?pakket=<beschermd|protect>#grotere-woning`
  (`data-zv-event="climax_hardware_link"`, `data-cta-name="uitbreiding_hardware"`,
  `data-solution-type`, `data-package-sku`), styled like the Uitbreidingen button it replaces, and
  the hint "Grotere woning of meer verdiepingen? U breidt uit met extra sensoren, zonder toeslag
  per maand." (`.pcard__plus-hint`). The NAMI cards are byte-identical to `main` (checked on the
  server HTML, §6).
- **Drawer:** a Beschermd or Protect line has nothing to clone (no addons/terms group on the
  card), so its row renders with no option block and no Woning control.
- **Meer informatie modal:** no Woning box; the same link and hint instead. `care`/`guard` no
  longer carry `plus` in `#opl-modal-data`; their items moved to the hardware page.
- **Footnote:** "Alleen bij Inzicht, Zeker en Alert: +€4/mnd per extra verdieping of per 100 m²
  extra woonoppervlak. Beschermd en Protect breidt u uit met extra sensoren. …" Names come from
  `zv-package-name`, the amount from `zv_woning_unit_cents`; the rest of the line is unchanged. The
  same line sits under both grids, as specified.
- **Hardware page `#grotere-woning`** (above the product rows): one set per package per extra
  verdieping, each item mapped to an existing HW row by its `k`:

  | Package | Item | HW row (`k`) | Qty |
  |---|---|---|---|
  | Beschermd | Rookmelder | `rookmelder` (CL005) | 1 |
  | Beschermd | Magneetcontact | `magneetcontact_dc23` (CL001) | 2 |
  | Beschermd | Locatiesensor | none on this page: "Op aanvraag, uw adviseur neemt dit mee", no price or SKU | 1 |
  | Protect | Fotobewegingsmelder | `foto_bewegingsdetector_868` (CL003A) | 1 |
  | Protect | Deurcontact | `magneetcontact_dc23` (CL001) | 1 |

  "Voeg set toe" adds the mapped rows to the existing `state.lines` as Kopen, on top of what is
  there (one click per extra verdieping). `?pakket=beschermd|protect` highlights that set and
  scrolls to the block. `captureSource()` already stored `pakket_intent`; it reaches the callback
  payload as `source.pakket_intent` (verified, §6). Conversion stays phone/callback only. The
  page's eyebrow/lead settings (Mijn Thuis/camera) are unchanged; the block's copy names both
  lines and makes no camera claim.
- **Legacy Ontzorgpakket on a Climax line** is left alone (no guard rule). Before this change it
  could be written two ways, both from the Climax card's "Extra diensten (optioneel)" group
  (`data-group="terms"`): (a) the card's "In winkelwagen" (`readCardOptions()` put the checked
  "Ontzorgpakket" into `properties['Abonnement']` in `/cart/add.js`), and (b) the cart drawer,
  which cloned that group into the line (`hydrateLineOptions()`) and wrote `Abonnement` via
  `/cart/change.js`. The modal, Vergelijk pakketten and the pakket-matcher never wrote it. So a
  legacy value is exactly `Abonnement: Ontzorgpakket`, with no amount (the add-on is "Prijs volgt").
